# Feishu QR Code Connector

中文名称：二维码生成器飞书接入。

帮助用户的 AI 完成配置：用户提供一次准确多维表链接、确认首列、点击生成 Key 并安全输入；AI 完成其余字段、按钮、自动化与验收。

## 固定服务与输出

- Heyvoxo Skills：<https://ops.heyvoxo.com/skills>（仅当前获准飞书组织成员可登录）。公开此 Skill 不代表任何组织都可使用私有工作台。
- 创建 Key 的入口：`https://ops.heyvoxo.com/skills?table_url={encodeURIComponent(用户原始链接)}#feishu-qr-code-connector`。
- 请求：`POST https://api.heyvoxo.com/v1/feishu/qr-by-sku`。
- 健康检查：`GET https://api.heyvoxo.com/health`。
- 请求头：`Content-Type: application/json`、`Authorization: Bearer <表格专属 Key>`。
- 请求体仅包含 `{"sku":"当前触发行的 SKU"}`。不要传链接、表 ID、行 ID、产品名称、设计或尺寸参数。
- Heyvoxo 按 Key 的创建者和传入 SKU 查询目标链接；首次调用自动创建并保存，重复调用复用原链接，然后生成默认黑白 PNG，写回绑定表同一 SKU 行的 `售后二维码图片` 附件列。默认二维码区域 30 × 30 mm，底部另加 5 mm SKU 文字区，成品 30 × 35 mm、600 DPI 对应 709 × 827 像素。M 容错、四模块静区，SKU 不侵入安全留白。长 SKU 自动换行并增加文字区高度，以接口返回的 width、height 为准；打印时按成品实际尺寸设置。PNG 携带 600 DPI 元数据，文件名包含 SKU 和成品尺寸。
- Key 绑定单张表，不能跨表使用。系统只存哈希，支持轮换和撤销。不要使用旧域名或 zctech 接口。

## 1. 确认目标表

先询问用户要接入的准确飞书多维表链接；如果本次对话已经提供，直接复用，不再次索取。链接须包含 `table=tbl...`。不得按历史记录、名称或最近访问自行选择表。

只读查看该表，然后明确提醒并询问用户：

> 目标表是「{表名}」，首列表头是「{实际表头}」。接入要求首列为小写 `sku`。请确认将首列设置/保持为 `sku`，并继续接入？

即使已有 `sku` 也须确认。未经确认不改字段、不建自动化。若无法访问，先帮助用户授予所需访问权限，不猜测表信息。

## 2. 补齐字段和权限

确认后保留原数据，将首列名称设置为 `sku`，类型为单行文本。若类型转换可能破坏数据，先说明具体影响并让用户决定。

- 没有 `售后二维码图片` 时创建同名附件字段。若同名字段类型不符，停止并说明冲突；经用户同意重命名旧字段保留内容，再创建准确同名附件字段。不要静默覆盖数据或使用名称相近的新字段。
- 创建或复用 `生成售后二维码` 按钮字段，以及 `Heyvoxo 生成售后二维码` 自动化，避免重复。
- 确认管理员提供的 Heyvoxo 飞书自建应用已加入目标多维表，具备读取记录、更新记录和上传附件所需权限。无权限时让管理员配置；不向用户索要 App Secret。
- 不添加设计、模板、DPI、尺寸字段。无需提前在 Heyvoxo 录入 SKU；飞书传入的有效 SKU 会自动建档。

## 3. 配置自动化并安全填入 Key

1. 触发：当前行按钮被点击，并且当前行 `sku` 非空。
2. 配置上述 POST 地址和 JSON 请求头。
3. JSON 的 `sku` 值必须通过飞书的动态字段选择器引用触发行 `sku`，不要把示例占位符作为字面量保存。
4. 创建 Authorization 请求头，打开并聚焦其值输入位置。
5. 使用用户此前的原始表链接构造上述 Skills 入口并打开。用户无需再次输入表链接；页面显示带入的目标表后，点击“一键生成表格专属 Key”。已有有效连接时页面提示重新生成会让旧 Key 失效，先确认这是用户要更新的自动化。
6. 若 AI 客户端提供真正的安全凭证输入窗口，可让用户输入并由该机制直接填入 Authorization，前提是秘密不会回传给模型、日志或聊天。否则使用飞书原生输入框，由用户亲自填写。不要声称普通聊天弹窗是安全窗口。
7. 该页面复制按钮提供完整 `Bearer …` 值；直接粘贴，不重复添加前缀。如果其他客户端只提供原始 Key，则应先在目标输入框预置 `Bearer `。
8. AI 不得读取、复制、记录、复述或截图 Key，也不要在用户输入后抓取含凭证的 DOM/截图。用户确认已输入后继续保存、启用与测试，不让用户重复配置非秘密字段。

只有持有用户授权且具备相应操作工具时才执行以上写操作。若当前 AI 不能操作浏览器/飞书，应给出准确的下一步人工操作，不谎报配置完成。

## 4. 验收真实请求与新图片

- 测试前记录目标行附件的非秘密标识/更新时间，以区别旧图片。
- 点击目标 SKU 对应行的按钮一次，查看该次 HTTP 响应：必须为业务 JSON，HTTP 200 且 `ok: true`、`sku` 正确、`updated_field: 售后二维码图片`。
- 飞书自动化显示“成功”或健康检查 200 都不能代替上述业务验收；HTTP 动作可能把 403 当作执行成功。
- 确认同一行产生新的 PNG 附件，尺寸 709 × 709。实际扫码或解码下载的 PNG，核对目标与 Heyvoxo 保存的链接一致。未完成扫码就明确标记未完成；正式打印前建议实物打样扫码。
- 绑定飞书表中不存在或重复的 SKU 应报错并保留旧附件，不要为测试修改用户真实 SKU 数据。

## 5. 排错与停止条件

- DNS、TLS、超时或 Cloudflare HTML 403：记录实际 POST 的时间、状态和 Ray ID，交 Heyvoxo 管理员核查 `api.heyvoxo.com` 路由。不要自行更换域名、关闭鉴权/防护或索要服务器登录信息。
- 401：确认 Authorization 格式、表绑定和 Key 是否已轮换。复用已提供链接打开 Skills 入口，由用户安全输入新 Key；轮换将中断使用旧 Key 的自动化，须明确告知。
- 403/422：检查登录组织、文档应用权限、首列和附件字段。
- 404/409：检查绑定飞书表是否存在、目标行 SKU 是否存在且唯一；不要求提前录入 Heyvoxo。
- 429：按响应提示等待，避免连续点击。未知结果先检查附件和日志，不盲目重复生成或轮换。

完成后报告确认的表名、字段与自动化状态、测试 SKU、实际业务响应、新 PNG 回写与扫码结果。失败时指出具体阻塞和下一步。不要输出任何密钥、访问令牌或附件临时下载地址。

## 记录归属与保存

- Key 绑定创建它的飞书登录账号。请求仍只传 SKU，不传用户 ID 或姓名，不尝试识别按钮的实际点击者。多人共用 Key 时，记录归 Key 创建者。
- 网页和飞书入口创建的记录都会保留在编辑页；普通成员只看自己的记录，指定管理员可统一查看所有成员记录。
- 同一用户重复调用同一 SKU 复用原链接，不同用户相同 SKU 互相隔离。PNG 上传飞书后 Heyvoxo 不长期保存图片；记录不重复保存用户名，显示名称来自既有飞书登录会话。
